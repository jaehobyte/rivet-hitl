# RIVET Interview — 즉시 문답 저장 · 요구사항 갱신 · 후속 질문

## 목적과 운영 모드
이 Skill은 사람 주도의 요구사항 인터뷰를 돕는다. 자동 오케스트레이터가 아니다. Discovery에서 생성한 `QUESTION_BACKLOG.md`를 출발점으로 사용한다.

- **TERMINAL (기본):** Codex가 질문하고 사용자가 그 자리에서 답한다. 이때 질문과 답변은 **별도 붙여넣기 없이** 자동으로 `INTERVIEW_NOTES.md`에 기록해야 한다.
- **PASTE:** 사람이 외부 업무 담당자에게 직접 질문한 후 실제 문답을 Codex에 붙여넣는다. 이때 전달받은 문답을 같은 형식으로 기록한다.
- 두 모드 중 실제 입력 방식에 맞는 것을 선택한다. `화자`·`발언 시각`·`출처` 필드는 기본적으로 만들지 않는다. 여러 출처를 섞어 구분이 필요한 경우에만 해당 기록에 최소한의 출처 메모를 추가한다.
- **중요:** 터미널 사용자가 답변했다고 해서 그 내용이 곧 공식 사내 정책이라는 뜻은 아니다. 답변에 유보/권한 부족이 드러나면 `SPEC.md`에서 미확정으로 관리한다.

## 우선순위 1: 터미널 문답은 반드시 즉시 디스크에 저장
**새 인터뷰 답변을 받으면 다른 추론·질문 생성·요약보다 파일 쓰기를 먼저 수행한다.** 채팅에 요약만 출력하는 것은 기록이 아니다.

### A. Codex가 질문을 하는 경우
1. 기존 `INTERVIEW_NOTES.md`를 읽는다. 없으면 생성한다. 완료된 INT 기록을 덮어쓰거나 삭제하지 않는다.
2. `QUESTION_BACKLOG.md`에서 질문 ID를 선택한다. 새로운 질문이면 Q-ID를 먼저 추가한다.
3. 사용자에게 묻기 **직전**, 다음 INT 번호로 `Q:` 원문과 `A: [답변 대기]`를 **실제 파일에 저장**한다. 이후 질문을 터미널에 표시한다.
4. **다음 사용자 메시지가 질문에 대한 답이면**, 다른 행동보다 먼저 `[답변 대기]`를 그 답변 원문으로 교체하고 저장한다. 완료된 기록은 이후 수정하지 않는다. 답변이 길어도 의미가 달라지도록 다듬지 않는다.
5. 사용자가 `건너뛰기`, `답변 보류`라고 명시했으면 답변을 지어내지 않는다. 대기 항목은 `A: [보류 — 사용자 요청]`로 처리하고 질문 상태를 `deferred`로 둔다.
6. 다음 질문을 생성하기 전에 파일을 다시 읽어 **해당 Q/A가 실제로 저장되었는지 확인**한다. 도구 권한·파일 오류로 저장하지 못했다면 그 사실을 즉시 보고하고, 저장 완료라고 주장하지 않는다.

### B. 외부 인터뷰 문답을 붙여넣은 경우
1. 실제 질문과 답변이 모두 주어지면 새로운 `INT-xxx` 블록으로 `Q:`와 `A:`를 원문 그대로 추가한다. Q-ID가 알려졌으면 붙이고, 없으면 임의의 실제 질문을 만들지 않는다.
2. 답변만 주어지면 관련 질문을 바로 앞 터미널 대화 또는 `QUESTION_BACKLOG.md`에서 **정확히 확인할 수 있을 때만** `Q:`에 기록한다. 확인 불가능하면 `Q: [원문 미확인]`이라고 한 번만 표시한다.
3. 기록을 파일에서 다시 확인한 후 분석을 진행한다.

### 인터뷰 기록 최소 포맷

```markdown
# INTERVIEW_NOTES — Q&A 원문

## INT-001 · Q-001
Q: 장비 교정 만료일 당일에도 사용 가능한가요?
A: 사내 규정을 확인해야 해서 제가 지금 단정할 수는 없습니다.
```

- `INT-ID`는 순차 증가하며, `Q-ID`는 `QUESTION_BACKLOG.md`의 기존 표기를 유지한다 (`Q01`이면 `Q01`, `Q-001`이면 `Q-001`).
- 원문 파일은 Q/A의 원장이다. **Codex 해석·분류·중복 요약을 이 파일에 매번 복사하지 않는다.**
- 완료된 기록은 변경하지 않고, 정정이 필요하면 새 INT 항목으로 추가해 이전 ID를 참조한다.
- 개인 식별정보, 비밀번호, API 키 등 인터뷰와 무관한 비밀은 기록하지 않는다.

## 우선순위 2: 저장된 답변을 요구사항에 반영
Q/A 저장을 확인한 **후에만** 아래 순서로 처리한다.

1. **원자적 주장 추출:** 답변에서 확정된 사실, 잠정 제안, 아직 정하지 못한 업무 정책을 구분한다. `모른다`, `사내 규정 확인 필요`는 확인 완료가 아니다.
2. **Backlog 갱신:** `QUESTION_BACKLOG.md`의 관련 질문을 `answered / partial / deferred / needs_authority_check` 중 적절한 상태로 갱신한다. 연결된 `INT-ID`를 남긴다. 답변 하나가 해결한 다른 질문도 갱신하고 중복 질문을 지운다.
3. **SPEC 갱신:** `SPEC.md`의 FR/BR/NFR/CON/AC에 실제 확인 내용만 반영한다. 필요하면 `INT-xxx`만 근거로 연결한다. 원문 전체를 SPEC에 중복 복사하지 않는다.
4. **영향 재평가:** 중요한 정상·예외·동시성·복구 흐름 중 답변으로 달라진 부분만 재검토한다. `ARCHITECTURE.md`, `PLAN.md`가 이미 있다면 변경 영향이 있음을 표시하고 사람의 승인을 기다린다.

## 우선순위 3: 다음 질문의 가치 판단
다음 질문이 필요한 경우에만 `references/QUESTION_CRAFTING.md`를 참고한다.

- 제공된 README/코드/기존 INT에 이미 답이 있으면 묻지 않는다.
- 다른 답변이 나왔을 때 **핵심 FR, 업무 불변조건(BR), 중요 NFR/QAS, 아키텍처 결정, 핵심 수용 테스트(AC)** 중 무엇이 구체적으로 달라질지 설명할 수 있어야 한다 (Decision Delta).
- 현업 정책은 업무 담당자에게, 기술 수단은 Architecture로, 범위·위험 수용은 Human Gate로 보낸다.
- 실제 필요한 P0를 우선하고 P1/P2는 인터뷰 비용과 재작업 위험을 고려해 유예한다.
- 정책 결정권자가 `미확정`이라고 답했다면 같은 질문을 반복하지 않고 권한자 확인 대상으로 남긴다.
- 질문을 계속해야 할 근거가 없다면 인터뷰 종료를 권고한다. 모든 Backlog 질문을 소진할 필요는 없다.

## 터미널 표시 규칙 — 토큰 최소화
문답을 기록한 후에는 다음 세 가지 중 필요한 것만 간략히 출력한다.
- `기록: INT-xxx 저장됨 / Q-xxx 상태` (실제 파일 확인 뒤에만)
- `SPEC: 변경된 핵심 규칙 요약 1~2문장` (변경이 있을 때만)
- `다음 질문: Q-xxx ...` 또는 `추가 질문 없음 — Human Gate 판단 요청`

`미제공 화자`, `미제공 시각`, `사용자가 채팅에 붙여넣은 텍스트`, 장황한 `Codex 해석` 블록을 반복 출력하지 않는다.

## 종료 및 사람 승인
핵심 Must FR/BR, 중요한 NFR의 우선순위 또는 제약, 정상/실패 흐름, 주요 AC가 아키텍처를 정할 만큼 명확하고 남은 P0가 해결되거나 사람이 위험을 수용했다면 종료를 권고한다. **Architecture로 자동 이동하거나 Must/Should/Out을 임의 승인하지 않는다.**
